## 2. 代码库问题

### 2.1 问题描述
代码库缺少旧版本的 HAL 驱动源文件，CMake 配置引用了以下不存在的文件：
- `hal_uart/v120/hal_uart_v120.c`
- `hal_uart/v100/hal_uart_v100.c`
- `hal_adc/v151/hal_adc_v151.c`
- `hal_spi/v100/hal_spi_v100.c`
- `hal_watchdog/v100/hal_watchdog_v100.c`
- `hal_rtc_unified/v100/hal_rtc_v100.c`
- `hal_pinmux/riscv70/...`
- `hal_pmp/riscv70/...`

### 2.2 根本原因
SDK 使用 Kconfig 配置系统选择驱动版本，但实际代码库只包含最新版本（V151/V153），旧版本文件缺失。

### 2.3 修复方案
创建符号链接将旧版本指向现有版本：

```bash
# UART 驱动
cd src/drivers/drivers/hal/uart/
ln -s v151 v120
ln -s v151 v100

# ADC 驱动
cd src/drivers/drivers/hal/adc/
ln -s v153 v152
ln -s v153 v151

# SPI 驱动
cd src/drivers/drivers/hal/spi/
ln -s v151 v100

# Watchdog 驱动
cd src/drivers/drivers/hal/watchdog/
ln -s v151 v100

# RTC 驱动
cd src/drivers/drivers/hal/rtc_unified/
ln -s v150 v100

# Pinmux 驱动
cd src/drivers/drivers/hal/pinmux/
ln -s bs2x riscv70

# PMP 驱动
cd src/drivers/drivers/hal/pmp/
ln -s v31 riscv70
ln -s v31 riscv_31
```

## 3. Kconfig 配置系统问题

### 3.1 问题描述
编译时生成的 `mconfig.h` 只有版权头，没有实际的宏定义，导致：
- `CONFIG_UART_USING_V151` 等宏未定义
- CMake 无法正确配置源文件列表
- 编译失败："No SOURCES given to target"

### 3.2 根本原因
`src/build/script/usr_config.py` 中的 `mconfig()` 函数在加载 Kconfig 时，当前工作目录不在项目根目录，导致 `osource` 命令无法找到其他 Kconfig 文件。

### 3.3 修复方案
**文件**: `src/build/script/usr_config.py`

**修改内容**（第 40 行前添加）：
```python
def mconfig(command, chip, core, target, output, assignments = None, root=""):
    if not root:
        root = root_path

    kconfig = os.path.join(root, "config.in")
    print(kconfig)
    print(os.getcwd())

    display_style = "default selection=fg:white,bg:blue"
    target = target.replace('-', "_")
    target_conf = os.path.join(root, "build", "config", "target_config", chip, "menuconfig", core, "%s.config" % target)
    config_header = '''# Generated by Kconfig Tool.
# Note: !!!This file can not be modify manually!!!
'''
    autoheader_header = '''/* Copyright (c) HiSilicon (Shanghai) Technologies Co., Ltd. 2022-2022. All rights reserved. */
'''
    mconf_set_env(display_style, target_conf, config_header, autoheader_header, output)

    # ===== 添加这一行 =====
    os.chdir(root)
    # ======================

    kconf = Kconfig(filename=kconfig)
```

## 4. 配置自动重置问题

### 4.1 问题描述
每次编译时，`.config` 文件会被重置为最小配置，丢失所有驱动版本设置。

### 4.2 根本原因
`target_config.py` 中的 `reload_kconfig: True` 会在编译时重新生成配置。

### 4.3 修复方案
**文件**: `src/build/config/target_config/bs21e/target_config.py`

**修改内容**:
```python
# 修改前
'reload_kconfig': True,

# 修改后
'reload_kconfig': False,
```

## 6. 遗留问题

### 6.1 驱动版本兼容性
创建符号链接是一种临时解决方案。实际项目中应该：
- 确认芯片实际使用的 IP 版本
- 在 `.config` 中配置正确的版本选项
- 或者补充缺失的旧版本驱动代码

### 6.2 KEYSCAN 配置
`KEYSCAN_ENABLE_COL` 和 `KEYSCAN_ENABLE_ROW` 有范围限制：
- 全键盘模式: COL=8, ROW=16
- 六键模式: COL=2, ROW=3

配置超出范围会导致 Kconfig 警告并回退到默认值。

### 6.3 IR 驱动编译问题
IR 驱动依赖 PWM 的 `uapi_pwm_set_group()` 函数，如果不需要 IR 功能，可以在配置中禁用：
```
# CONFIG_DRIVER_SUPPORT_IR is not set
```

## 附录：完整修复脚本

```bash
#!/bin/bash
# fix_sdk.sh - 一键修复 SDK 编译问题

SDK_ROOT="/mnt/d/fbb_bs2x/fbb_bs2x/src"

echo "[1/3] 创建 HAL 驱动符号链接..."

# UART
cd ${SDK_ROOT}/drivers/drivers/hal/uart/ && ln -sf v151 v120 && ln -sf v151 v100

# ADC
cd ${SDK_ROOT}/drivers/drivers/hal/adc/ && ln -sf v153 v152 && ln -sf v153 v151

# SPI
cd ${SDK_ROOT}/drivers/drivers/hal/spi/ && ln -sf v151 v100

# Watchdog
cd ${SDK_ROOT}/drivers/drivers/hal/watchdog/ && ln -sf v151 v100

# RTC
cd ${SDK_ROOT}/drivers/drivers/hal/rtc_unified/ && ln -sf v150 v100

# Pinmux
cd ${SDK_ROOT}/drivers/drivers/hal/pinmux/ && ln -sf bs2x riscv70

# PMP
cd ${SDK_ROOT}/drivers/drivers/hal/pmp/ && ln -sf v31 riscv70 && ln -sf v31 riscv_31

echo "[2/3] 修复 usr_config.py..."
cd ${SDK_ROOT}/build/script/
sed -i 's/kconf = Kconfig(filename=kconfig)/os.chdir(root)\n    kconf = Kconfig(filename=kconfig)/' usr_config.py

echo "[3/3] 禁用 reload_kconfig..."
cd ${SDK_ROOT}/build/config/target_config/bs21e/
sed -i "s/'reload_kconfig': True/'reload_kconfig': False/" target_config.py

echo "修复完成！可以执行: python3 src/build.py standard-bs21e-1100e"
```
